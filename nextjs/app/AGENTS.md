# AGENTS.md

A Next.js App Router app over a Constructive database. Most screens are generated from the database's `_meta`; you change the app by editing those generated configs, not by writing screens from scratch.

## Where things live

- `src/resources/<resource>.ts`: one config per table: labels, fields, input types, select options, list columns, form order, search fields, default sort. **Edit this first** for any change to a list, form or detail view, and **delete its first line (`// @generated …`) before you edit**, so the file is yours and later generator runs leave it alone.
- `src/resources/index.ts`: the resource registry and the sidebar order.
- `src/app/(app)/<resource>/page.tsx` and `[id]/page.tsx`: the list and detail routes. `src/app/(app)/page.tsx` is the dashboard; `src/config/app.ts` holds the app name and tagline.
- `src/app/(auth)/`: sign-in, sign-up, check-email, verify-email, forgot-password, reset-password.
- `src/components/ui/`: installed blocks source (`resource-kit`, `auth-pages`, `dashboard-tiles`, `workspace-kit`, primitives). It is yours to edit.
- `src/lib/`: session and token (`lib/auth`), the ORM client `db`, `fetchAll` and `describeError` (`lib/graphql`), endpoints (`lib/runtime`), `ormSource` (`lib/resources`).
- `src/app/(app)/error.tsx`, `src/app/error.tsx`, `src/app/global-error.tsx` and `src/app/not-found.tsx`: the error boundaries and the 404 page. A page that throws shows the error inside the shell with a "Try again" button (`src/components/app-error.tsx`), so you don't need a try/catch around a whole page.
- `src/config/nav.ts`: the sidebar's first section, the home row (`homeNav`) and hand-written pages (`customNav`), above the generated "Data" pages.
- `src/graphql/sdk/{auth,app}`: the generated SDK. Never edit it; run `pnpm codegen` after a schema change.
- `.constructive/`: `app-spec.json` (the AppSpec the app was built from), `meta.json` (the database's `_meta` at the last build) and `gen-state.json` (what the generator last wrote; don't edit it).

## Generated files

A generated file starts with `// @generated by gen:resources — delete this line to take ownership (body sha256:…)`. `pnpm gen:resources --meta <meta.json> [--spec <app-spec.json>]` rewrites a file only while that line is there, and removes generated files of tables that no longer exist. To customize a generated file by hand, delete that first line, then edit; the generator will leave it alone from then on. If you forget and edit below the line, the hash no longer matches: the generator leaves the file alone and lists it under `files.modified`, but the file stops following the database until you take it over. Prefer small edits to the resource config over replacing a page.

## Change this app

- **Data model or generated screens** (a new table, column or link; labels, select options, list columns, form order, sidebar order, dashboard tiles): these come from the AppSpec, not the code. The desktop writes `.constructive/app-spec.json` from the live database, so don't edit it: ask the desktop agent, which calls `plan_app` with the changed spec. `plan_app` applies only the difference to the database (a curated blueprint grows through `backend.extend`), then runs codegen and the generator. Don't change the database schema from inside the app.
- **Code** (a custom page, a domain block, the home screen, a config you own): edit files you own, run `pnpm lint:types`, then check the screen in `pnpm dev`.
- **Re-running the generator** is safe: `pnpm gen:resources --meta .constructive/meta.json --spec .constructive/app-spec.json` (`--dry-run` prints the summary without writing). It adds the files of new tables, rewrites untouched generated files, deletes untouched files of tables that are gone, and never touches `src/config/nav.ts` or a file you own. Run `pnpm codegen` first when the schema changed. Then read `hints` in the summary: each names a file you own or edited that misses something new, e.g. "src/app/(app)/page.tsx is yours; add the new resource donations to it by hand if needed". A hint shows once, on the run that brings the change.
- **Never edit a `@generated` file in place.** Delete its first line, so the file is yours, then edit it.

## Add a custom page

For a view the resources don't cover (a calendar, a report, a staffing board), add a route file and one sidebar entry. Never open or edit `src/components/app-shell.tsx`, the layouts (`src/app/**/layout.tsx`) or generated files, and don't open the kit, block or SDK sources to learn them: everything you need is below and in each item's docs. Placeholders: `<model>` is the ORM accessor from `src/resources/<resource>.ts` (`ormSource(db.<model>, …)`), `<resource>` its registry name, `<queryAll>` the plural key `findMany` returns, `<FIELD>` a field in CONSTANT_CASE.

**1. The route** `src/app/(app)/<slug>/page.tsx`: everything under `(app)` is behind sign-in and inside the shell.

```tsx
'use client';

import { useQuery } from '@tanstack/react-query';
import { CalendarDaysIcon, InboxIcon } from 'lucide-react';

import { db } from '@/lib/graphql/db';
import { describeError } from '@/lib/graphql/errors';
import { DashboardGrid, StatTile } from '@/components/ui/dashboard-tiles';
import { EmptyState, TableSurface, tableHeadClass, tableRowClass, ViewFrame } from '@/components/ui/workspace-kit';

export default function UpcomingPage() {
	const { data, isPending, error } = useQuery({
		// Under resource-kit's key for the resource, so creates and edits there refresh this view.
		queryKey: ['resource-kit', '<resource>', 'upcoming'],
		queryFn: () =>
			db.<model>
				.findMany({
					select: { id: true, <field>: true, <relation>: { select: { <labelField>: true } } },
					where: { <field>: { greaterThanOrEqualTo: new Date().toISOString() } },
					orderBy: ['<FIELD>_ASC'],
					first: 50,
				})
				.unwrap(),
	});
	const rows = data?.<queryAll>.nodes ?? [];
	return (
		<ViewFrame icon={CalendarDaysIcon} title='Upcoming'>
			<DashboardGrid>
				<StatTile label='Upcoming' value={data?.<queryAll>.totalCount ?? 0} loading={isPending} />
			</DashboardGrid>
			{error ? <p className='text-sm text-destructive'>{describeError(error)}</p> : null}
			{!isPending && rows.length === 0 ? (
				<EmptyState icon={InboxIcon} title='Nothing upcoming' />
			) : (
				<TableSurface>
					<thead className={tableHeadClass}>
						<tr><th>When</th><th>Where</th></tr>
					</thead>
					<tbody>
						{rows.map((row) => (
							<tr key={row.id} className={tableRowClass}>
								<td>{row.<field> ? new Date(row.<field>).toLocaleString() : '—'}</td>
								<td>{row.<relation>?.<labelField> ?? '—'}</td>
							</tr>
						))}
					</tbody>
				</TableSurface>
			)}
		</ViewFrame>
	);
}
```

**2. The sidebar:** append one entry to `customNav` in `src/config/nav.ts`. The shell lists these right below home, above the generated "Data" pages.

```ts
import { CalendarDaysIcon } from 'lucide-react';

export const customNav: CustomNavEntry[] = [{ label: 'Upcoming', href: '/<slug>', icon: CalendarDaysIcon }];
```

**3. Reading and writing rows** with `db` from `@/lib/graphql/db` (it sends the session token):
- `findMany({ select, where, orderBy, first, offset })` returns `{ <queryAll>: { nodes, totalCount, pageInfo } }`. `.unwrap()` throws on errors; `.execute()` returns `{ ok, data, errors }`.
- `where` takes per-field operators (`equalTo`, `in`, `greaterThan`, `lessThanOrEqualTo`, `isNull`, `includesInsensitive` on text) plus `and`, `or`, `not`. `orderBy` takes `<FIELD>_ASC`/`_DESC`. Your editor's types list them all. Search and filter only on the fields the generated filter type lists: not every column is in it.
- A related record's label: select the belongs-to object, `<relation>: { select: { <labelField>: true } }`, then read `row.<relation>?.<labelField>`. Has-many: `<children>: { select: { … }, first: 20 }`, then `.nodes`.
- **The API caps a page at 1000 rows: `first` above 1000 fails the whole request** ("The requested page size is too large"). For whole tables, use `fetchAll`, which pages by cursor and returns every row, typed by your `select`:
  `const rows = await fetchAll((page) => db.<model>.findMany({ select: { id: true }, where, ...page }));` (import from `@/lib/graphql/fetch-all`).
- Show a failed query or write with `describeError(error)` (from `@/lib/graphql/errors`), never `error.message`: it turns an unavailable database, a screen the database changed under, or an ended session into one sentence, and keeps the server's text for the rest. React Query doesn't retry those three.
- Writes: `db.<model>.create({ data, select: { id: true } })`, `.update({ where: { id }, data, select: { id: true } })` and `.delete({ where: { id }, select: { id: true } })`, each with `.unwrap()`. Then `queryClient.invalidateQueries({ queryKey: ['resource-kit', '<resource>'] })` (from `useQueryClient()`).
- Show dates and times in the user's locale and time zone, as the kit's formatters do: `new Date(value).toLocaleString()` (or `dateFormat` from `@/lib/intl`), never the raw ISO string. A date-only value (`2026-10-19`) is a calendar day, so format it with `timeZone: 'UTC'`, or it shows as the day before west of UTC.
- The signed-in user's id: `currentUserId()` from `@/lib/auth/token-manager`.
- JSON columns are typed as objects. To write an array to one, cast it: `<jsonField>: [{ type: 'text', text }] as unknown as Record<string, unknown>`.

**4. Building blocks** (props in braces). For any item's full API, run `pnpm dlx shadcn@4.13.1 view @constructive/<item>` and read its `docs`; don't open the kit's source.
- `@/components/ui/workspace-kit`:
  - **Views:**
    - `ViewFrame {icon, title, actions?, maxWidth?}`: the page frame, a 48px header over a scrolling column. Use one per page.
    - `SectionHeading {title, description?, actions?}`.
    - `SearchField {label, value, onChange}`.
    - `FilterGroup {label, value, options: {value, label, count?}[], onChange}`: filter pills.
    - `Segmented {label, value, options: {value, label}[], onChange}`.
    - `TooltipIconButton {label}`.
  - **Surfaces:**
    - `Panel {title?, description?, actions?, footer?}`: a card section.
    - `TableSurface {minWidth?}`: a table card. Put `tableHeadClass` on `<thead>` and `tableRowClass` on each `<tr>`.
    - `EmptyState {icon, title, description?, action?}`.
    - `KeyValueList {items: {label, value}[]}`.
    - `ToneBadge {tone}`, where tone is neutral, primary, info, success, warning, danger, violet or amber.
    - `MiddleTruncate {text, tail?}`.
    - Also `StatusBadge`, `IconTile` and `Bezel`.
  - **Helpers:** `formatCount`, `plural`, `nameList`, `focusRingClass`. For diagrams, the canvas pieces (`useCanvasViewport`, `CanvasSurface`, `NodeShell`, `CanvasWire`).
  - **Shell and nav** (`WorkspaceShell`, `SidebarFrame`, `NavSection`, `NavRow`) already frame the app in `app-shell.tsx`. Add pages through `customNav` instead.
- `@/components/ui/dashboard-tiles`:
  - `DashboardGrid` lays tiles out in 1–4 columns.
  - `StatTile {label, value, hint?, href?, icon?, loading?}`.
  - `ResourceCountTile {resource, label?, filters?}`.
  - `RecentRecords {resource, title?, limit?, filters?, sort?}`.
- `@/components/ui/resource-kit`: `ResourcePage {resource}` and `RecordDetail {resource, id}` are the generated screens. Embed them for a filtered copy of a list.
- `@/components/ui/button`: `Button {variant?: default | outline | ghost | destructive, size?: sm | default}`.
- The generated React Query hooks (`use<Model>Query`, `useCreate<Model>Mutation`) from `@sdk/app` work too.

## Use a domain block

For an app's primary screen (a chat, a board, a calendar), prefer a ready-made block from the `@constructive` registry over hand-built markup. The block draws; you feed it rows and handle its callbacks.

1. **Find one:** the desktop's `search_blocks` tool, or `pnpm dlx shadcn@4.13.1 search @constructive -q "<words>"`. Search for every primary screen, boards, pipelines and schedules included, and compose from the pieces in "Add a custom page" only when nothing fits.
2. **Read its API:** `pnpm dlx shadcn@4.13.1 view @constructive/<name>` prints the item; its `docs` field lists the components and props. Don't open the block's or the kit's sources to learn them.
3. **Install:** `pnpm dlx shadcn@4.13.1 add @constructive/<name>`. Never add `--overwrite`: it replaces files you may have edited under `src/components/ui/`.
4. **Wire it to data** with `db`, react-query and `fetchAll`. Map rows to the block's props, and call a mutation from its callback, then invalidate. For example, a parent row and its children feeding a presentational list with a submit callback:

```tsx
'use client';

import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';

import { db } from '@/lib/graphql/db';
import { fetchAll } from '@/lib/graphql/fetch-all';

export function ChildList({ parentId }: { parentId: string }) {
	const queryClient = useQueryClient();
	const { data: rows = [] } = useQuery({
		queryKey: ['resource-kit', '<child resource>', 'of', parentId],
		queryFn: () =>
			fetchAll((page) =>
				db.<child>.findMany({ select: { id: true, <field>: true }, where: { <parentKey>: { equalTo: parentId } }, orderBy: ['CREATED_AT_ASC'], ...page }),
			),
	});
	const add = useMutation({
		mutationFn: (text: string) => db.<child>.create({ data: { <parentKey>: parentId, <field>: text }, select: { id: true } }).unwrap(),
		onSuccess: () => queryClient.invalidateQueries({ queryKey: ['resource-kit', '<child resource>'] }),
	});
	// Replace the markup with the block's components, passing `rows` and `add.mutate` to its props.
	return <ul>{rows.map((row) => <li key={row.id}>{row.<field>}</li>)}<li><button onClick={() => add.mutate('New')}>Add</button></li></ul>;
}
```

5. **Make it the home page.** When the block is what the app is for (conversations in an agent app, a board in a task app), it is the screen people land on:
   - Delete the first line (`// @generated …`) of `src/app/(app)/page.tsx`, so the generator leaves it alone, and build the domain screen in that file, at `/`. Don't redirect: the home row stays marked as the current page only at `/`. A route of its own with a `customNav` entry is not enough, since people land on `/`.
   - Rename the home row in `src/config/nav.ts`: `homeNav = { label: '<Screen name>', icon: <Icon> }`. Further domain screens go in `customNav`, right below it, so the domain screens come first in the sidebar.
   - The generated table pages stay under "Data". For the old dashboard as a secondary page, copy the file to `src/app/(app)/overview/page.tsx`, delete the copy's first line (`// @generated …`) too, and add `{ label: 'Overview', href: '/overview', icon: … }` to `customNav`. Otherwise drop it.

## Adding UI

The blocks registry is configured in `components.json`. Add an item with:

```bash
pnpm dlx shadcn@4.13.1 add @constructive/<item>
pnpm dlx shadcn@4.13.1 search @constructive --query "<what you need>"
```

## Checks

- `pnpm lint:types`: type-check. Run it after every change.
- `pnpm dev`: dev server on `$PORT`.
- Next.js 16 differs from older versions: read the guide in `node_modules/next/dist/docs/` before using an API you are unsure of.

## Keep

- The token storage keys in `src/lib/auth/token-manager.ts`: the desktop signs the owner in through them.
- The `data-app-error` attribute on the error states (`src/components/app-error.tsx`, `src/app/not-found.tsx`): the desktop's render check fails a page that shows one.
- `NEXT_PUBLIC_*` endpoints come from `.env.local`, written by the desktop. Don't hard-code URLs.
